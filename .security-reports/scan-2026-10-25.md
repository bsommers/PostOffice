## What the Code Does RIGHT

- **TLS verification on by default** — `security.py:16` `insecure_skip_verify: bool = False`; the plugins use `CERT_REQUIRED` unless the flag is set (`mqtt_client.py:44`).
- **Secrets from environment** — `REDIS_HOST` read from env in `worker.py`; no hardcoded credentials found.
- **Input validation** — `SecurityConfig` and `TopicTrie` validate inputs before use.
- **No dangerous primitives** — no `eval`/`exec`, `os.system`, `shell=True`, `pickle` or unsafe `yaml.load`.
- **DLQ payload encoding** — payloads Base64-encoded, so no format injection into the DLQ envelope.
- **DLQ recursion guard** — DLQ publish failures do not loop.
- **Secrets hidden from repr/logs (fixed this session)** — `SecurityConfig.password` and `client_key_password` are `repr=False`; ControlPlane logs action and name only; router no longer logs payload bodies (`tests/test_p0_hardening.py`).
- **Manual AMQP ack by default (fixed this session)** — `amqp_client.py` no longer acks before delivery.

## Vulnerabilities Found

### [MEDIUM 6.5] Unauthenticated metrics listener bound to all interfaces — `src/postoffice/metrics.py:81`
**OWASP**: A05 — Security Misconfiguration
**Layer**: Backend
**CVSS**: 6.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:L)

**Evidence**:
```python
def start_server(self, port: int, addr: str = '0.0.0.0') -> None:
```
**Risk**: Anyone who can reach the port can read broker names, topic labels and traffic volumes, and can hold connections open.
**Fix**: Default `addr` to `127.0.0.1` and make exposure an explicit opt-in (env var or `set_metrics_port(port, addr=...)`); in containers, restrict via network policy.

### [MEDIUM 6.8] Unauthenticated Redis control channel, credentials stored in plaintext — `src/postoffice/control_plane.py:16-37`, `data_plane.py:16`
**OWASP**: A01 — Broken Access Control / A02 — Cryptographic Failures
**Layer**: Backend
**CVSS**: 6.8 (AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H)

**Evidence**: `redis.Redis(host=..., port=...)` with no password or TLS. `postoffice:brokers` hashes and the `add_broker`/`update_broker_security` Pub/Sub messages carry `SecurityConfig.to_dict()`, including passwords.
**Risk**: Anyone with Redis access can read every broker credential, or publish `add_broker`/`add_route`/`clear_state` and redirect or drop traffic.
**Fix**: Support `REDIS_PASSWORD`/`REDIS_TLS`/ACL user via env, document Redis as a trust boundary, and consider secret references (env/vault name) in place of inline credentials.

### [LOW 3.7] Default AMQP credentials — `src/postoffice/plugins/amqp_client.py:28-29`
**OWASP**: A07 — Authentication Failures
**CVSS**: 3.7 (AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N)

**Evidence**: falls back to `"user"` / `"password"` when none supplied.
**Risk**: A misconfigured client silently tries well-known credentials.
**Fix**: Default to `None` and fail fast with a `ValueError` when no credentials are given (or use the pika guest default only on localhost).

### [LOW 3.1] Certificate verification can be disabled — `mqtt_client.py:44,52`, `amqp_client.py:204`, `kafka_client.py:53`
**OWASP**: A02 — Cryptographic Failures
**CVSS**: 3.1 (AV:N/AC:H/PR:H/UI:N/S:U/C:L/I:L/A:N)

**Evidence**: `insecure_skip_verify` honoured by three plugins.
**Risk**: Opt-in only, but a flag in config synced through Redis could silently enable MITM exposure.
**Fix**: Log a WARNING whenever it is active; reject it when an env flag such as `POSTOFFICE_ENV=production` is set.
