<task name="wire_schema_into_router" type="auto">
  <files>src/postoffice/router.py</files>
  <action>
    Update `src/postoffice/router.py`:
    1. In `Router.__init__`:
       - Accept optional `schema_registry: Optional[BaseSchemaRegistry] = None`.
       - Initialize `self.schema_registry = schema_registry or InMemorySchemaRegistry()`.
       - Initialize `self.converter = SchemaConverter(self.schema_registry)`.
    2. In `Router.add_route`:
       - Accept `input_format: Optional[str] = None`, `input_schema: Optional[str] = None`, `output_format: Optional[str] = None`, `output_schema: Optional[str] = None`, `wire_format: bool = False`.
       - Store schema metadata in route configuration dict.
    3. In `Router.route`:
       - Check if route requires transformation (`output_format` specified and differs from `input_format`, or schemas specified).
       - In routing loop, before calling `clients[target_client].publish(...)`:
         - If transformation configured:
           - Attempt deserialize incoming bytes using `route_config["input_format"]` and `route_config.get("input_schema")`.
           - Attempt serialize record dict using `route_config["output_format"]`, `route_config.get("output_schema")`, and `wire_format`.
         - On exception (validation, decoding, or schema error):
           - Record metric `self.metrics.record_error(source_client, "schema_validation_error")`.
           - Invoke `self._route_to_dlq(source_client, source_topic, message, error=f"Schema transform error: {e}", ...)`
           - If DLQ handled: do not publish to target; proceed to next route or return.
  </action>
  <verify>
    <command>PYTHONPATH=src .venv/bin/python -m unittest discover tests/</command>
  </verify>
</task>
