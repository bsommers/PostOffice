# Quick Task 261102-p3b: Protocol Adapters (Kafka K1–K5, AMQP A1–A6, MQTT M1–M3) & Outage Drills (P3-2)

## Goal
Implement the Phase 3 protocol adapter delivery guarantees in Rust (`native/libpostoffice/src/adapters.rs`) and Python (`src/postoffice/plugins/{kafka_client,amqp_client,mqtt_client}.py`), exposed via C ABI (`include/postoffice.h`) and verified with hermetic and outage/restart drill tests (`tests/test_phase3_adapters_and_drills.py`):

1. **Kafka Adapter (`KafkaOffsetTracker` in Rust + `KafkaClient` in Python, K1–K5):**
   - Contiguous offset completion watermark tracker per `(topic, partition)`:
     - `poll_offset(topic, partition, offset)` registers an in-flight offset.
     - `ack_offset(topic, partition, offset) -> Option<i64>` marks `offset` completed and returns `Some(highest_contiguous_offset)` only when the contiguous watermark advances (solving K1/K2 out-of-order completion hazard by design).
   - `enable.auto.commit=False` and `enable.auto.offset.store=False` in consumer config.
   - Producer `poll(0)` in `_consume_loop` so delivery reports fire even when no new `publish()` calls occur.

2. **AMQP Adapter (`AmqpAdapterState` in Rust + `AmqpClient` in Python, A1–A6):**
   - Publisher confirms (`confirm_delivery`) and `mandatory=True` unroutable detection.
   - Per-connection declared-queue cache (`_declared_queues`) so queues are declared once per connection rather than on every `publish()`.
   - Prefetch back-pressure (`basic_qos(prefetch_count=...)`) and reconnect loop with exponential backoff (`1, 2, 4, ..., 30s`), clearing `channel`/`connection` on disconnect so publishes buffer and flushing on reconnect.

3. **MQTT / NanoMQ Adapter (`MqttAdapterState` in Rust + `MqttClient` in Python, M1–M3):**
   - QoS 0 confirms immediately on `rc == 0`; QoS >= 1 tracks `mid` in `_inflight` and invokes `on_confirm` only when `_on_publish` (`PUBACK`) fires.
   - `_on_connect` checks `reason_code` failure before subscribing/flushing.
   - Reconnect backoff (`reconnect_delay_set(1, 30)`).

4. **Kill / Restart / Broker-Outage Drills (`tests/test_phase3_adapters_and_drills.py`):**
   - Out-of-order Kafka completion + mid-batch consumer crash/restart drill (proving zero message loss and no offset committed past an unacknowledged gap).
   - AMQP publisher confirm, unroutable `NackError`/`UnroutableError`, prefetch back-pressure, and broker outage/reconnect drill.
   - MQTT QoS 1 `PUBACK` confirm, `rc != 0` failure, and broker outage/reconnect drill.
