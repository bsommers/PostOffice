    Author a rigorous, multi-dimensional technical spike report evaluating:
    1. PostOffice Workload Profile:
       - Multi-protocol ingress/egress frame demuxing & forwarding.

       - Redis state sync and distributed control plane.
    2. Candidate Language Matrix:
       - **Python 3.12+** (Current Baseline): C-extensions, GIL dynamics, throughput ceilings, memory footprint.
       - **Go**: Goroutines, channel concurrency, pure Go broker drivers (franz-go, paho.golang, amqp091-go), GC latency characteristics, Docker scratch footprint.
       - **Rust**: Tokio async runtime, memory safety without GC, zero-cost abstractions, driver ecosystem (rdkafka, rumqttc, lapin), PyO3 hybrid FFI seam.
       - **Zig**: C-interop strengths, explicit memory allocation, lack of native broker libraries (heavy reliance on C FFI), pre-1.0 language churn risks.
       - **C / C++**: Maximum hardware performance vs manual memory management, vulnerability surface, build system complexity, low productivity.
    3. Benchmark & Architectural Comparison:
       - Expected msg/sec throughput per core.
       - Memory footprint (RSS).
       - Tail latency (p99/p99.9) under load.
       - SDK/Library ecosystem maturity score for MQTT, AMQP 0-9-1, Kafka, and Redis.
    4. Migration Strategies:
       - Strategy A: Pure Python Optimization (radix trie, cython).
       - Strategy B: Hybrid Python + Rust PyO3 Core (Python facade/config + native Rust routing engine).
       - Strategy C: Full Go Rewrite.
       - Strategy D: Full Rust Rewrite.
    5. Final Decision Matrix & Strategic Recommendation.
